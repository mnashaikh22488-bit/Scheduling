1. Learn the concept

See exactly what changes between the two priority algorithms.

How it works

At each decision point, choose the highest-priority process among the processes that have already arrived. Once selected, it runs until completion.

1. Check processes that have arrived 2. Choose highest priority 3. Run it completely 4. Advance time 5. Repeat until all processes finish

🚫 No preemption

A running process is never interrupted by a newly arrived process.

🎯 Decision point

The CPU chooses again when the current process finishes.

⚠️ Risk

Low-priority processes can wait for a long time (starvation).

How it works

At every relevant time, compare the running process with newly arrived processes. A higher-priority arrival can interrupt the current process.

1. Find processes that have arrived 2. Pick highest priority 3. Run for 1 time unit 4. Check for a higher-priority arrival 5. Preempt if required 6. Repeat until completion

🔄 Preemption

A running process may be interrupted by a higher-priority process.

⏱️ Frequent checks

Scheduling decisions can happen whenever a new process arrives.

⚠️ Risk

Context switching can increase overhead and starvation is still possible.
